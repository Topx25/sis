# Git Flow Rules

You must adhere to the full Git Flow methodology for all code modifications, additions, and structural changes in this workspace.

1. **Never commit directly to `main` or `master`**.
2. **Always create an appropriately named branch** before making any changes. Use prefixes such as `feature/`, `bugfix/`, `hotfix/`, or `chore/` (e.g., `feature/add-new-route`).
3. **Commit changes frequently** with clear, descriptive commit messages.
4. **Merge branches back** into the main or development branch (depending on the repository setup) only after the work is complete and tested. 
5. Always resolve merge conflicts by ensuring the structural integrity of the project is maintained.
